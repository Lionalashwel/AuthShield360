## ١) نظرة عامة

AuthShield 360 نظام مصادقة محلي بالكامل (لا إنترنت ولا قواعد خارجية) يطبّق منهجية المصادقة حسب المخاطر:
كل محاولة دخول تُقيَّم فورًا بمحرك خطر تكيّفي من **0 إلى 100** مع **أسباب مفسّرة**، ثم يُتخذ قرار حسب النطاق:

- 🟢 **LOW (0–30):** دخول مباشر (سيناريو 1) أو خطوة OTP عند الطلب (سيناريو 2/3).
- 🟡 **MEDIUM (31–69):** **موافقة عبر الجهاز الموثوق** (Cross-Device Approval) بأسلوب Apple/Google، أو بديل البريد الإلكتروني + OTP.
- 🔴 **HIGH (70–100):** قفل فوري للحساب + تنبيه للمشرف.

الإصدار v2 أضاف أربعة مكوّنات رئيسية: **بوابة مدرسية بسياسات RBAC صارمة**، **استرداد الحساب وإعادة ضبط MFA**، **لوحة التحقيق الرقمي (Forensics)** لإعادة بناء الخط الزمني للأحداث، و**لوحة أداء مقارنة سيناريوهات المصادقة** بزمن حقيقي `elapsed_ms`.

## ٤) الأمان: العوامل والنطاقات

| العامل | الوزن | ملاحظة |
|--------|------:|--------|
| F_TIME_ANOMALY (خارج 07:00–23:00) | +15 | |
| F_NEW_IP (شبكة فرعية غير مألوفة للمستخدم) | +25 | |
| F_NEW_DEVICE (بصمة مجهولة) | +30 | بمفردها = LOW |
| F_UNRECOGNIZED_DEVICE | +30 | |
| F_CONSECUTIVE_FAILURE | +20/محاولة | الثانية ⇒ +40 |
| F_IMPOSSIBLE_TRAVEL (> 1,000 كم/دقيقة) | +40 | Haversine عبر GEO_TABLE |
| F_BLACKLISTED_IP | +45 | ضمن القائمة السوداء |
| تجميع مع فهرسة | 0–100 | levels: LOW/MEDIUM/HIGH |

- **ثبات/تشفير:** كلمات المرور `SHA-256 + pepper` (مستوى تجريبي)، رموز الجلسات عشوائية، بيانات TOTP/RFC 6238 بنافذة 30 ثانية + كشف انتهاء الصلاحية، كوكي الوثوق AES-256-GCM لمدة سنة قابلة للإلغاء.
- **مكافحة قفل ذكي:** 3 محاولات كلمة مرور خاطئة ⇒ قفل بلا كشف وجود الحساب (تأجيل فشل غير معروف الهوية)، محاولات OTP لا تقفل الحساب.
- **RBAC:** سيناريو 3 لطلاب يُحوَّل إلى `HIGH_RISK_BLOCK (UNAUTHORIZED_ROUTE)`، وبوابة المدرسة بحواجز `portalGate(roles)` على المخدم (403).

## ٦) الاسترداد والتحقيق والأداء

### استرداد الحساب / إعادة ضبط MFA
`POST /api/recovery/request` (identifier → verifyCode 6 خانات) → `POST /api/recovery/reset` (تدوير TOTP + تغيير كلمة المرور + إصدار 10 رموز استرداد أحادية الاستخدام) → `POST /api/recovery/validate` (استهلاك الرمز مرّة واحدة). يُسجَّل `RECOVERY_REQUEST/RESET/CODE_VALID` في سجل الأحداث والتنبيهات.

### التحقيق الرقمي
`/api/forensics/{summary,entities,timeline,cases}` — الخط الزمني يعيد ربط الأحداث (رمز مرجعي `ref` + نوع الحدث + زمن) عبر نطاق المستخدم/IP/الجهاز/النتيجة؛ القضية تلتقط الأدلة تلقائيًا؛ التصدير بصيغة **Markdown** يعطي تقرير أدلة جاهزًا للأرشفة.

### الأداء (Benchmark)
`/api/benchmark` يقرأ `elapsed_ms` الحقيقي من `audit_trail` ويقارن السيناريوهات الثلاثة: عدد المحاولات، متوسط زمن الدخول، عدّادات النجاح/الفشل/الحجب — مؤشر لإثبات فعالية الحل.

## ١٠) ملاحظات وإخلاء مسؤولية

منصة تعليمية/عرضية — ليست بديلًا عن موفّر هوية معتمد (Auth0/Keycloak/Entra ID) في بيئة إنتاج. كلمات المرور تجريبية (SHA-256+pepper)؛ يُستبدل بـ argon2/scrypt في الإنتاج.
